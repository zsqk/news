我看了部分 [Alex Russell 的原文](https://infrequently.org/2024/11/if-not-react-then-what/),
完整看了這篇[翻譯文章](https://www.infoq.cn/news/Ssc0h0HBY7xkN1uk4P4t).

下面是我的一些看法:

## Frameworkism

Web 開發者並不是主動要被框架束縛, 在前端 (客戶端) 開發中, Android, iOS,
微信小程序, 鴻蒙應用等, 都在實現更多前端功能的前提下限制了前端的開發流.
而 Web 自身的設計在相同場景下相比其他前端開發技術棧來說交互嚴重不足.

那我們有交互需求的時候應該怎麼辦? 直接操作 DOM 太繁瑣, 並不是一種現代化的方案,
所以我們在 Web 的基礎上需要框架, 而不是直接寫 HTML + JS + CSS.

## Why SPA

SPA 不是必要的, 但是 Web 應用而不是 Web 網頁是必要的,
因為將 Web 作為應用會讓整體前端技術棧層次更清晰.
而 SPA 是實現 Web 應用的一種直觀的方式, 與其他端開發的架構變得類似.

隔行如隔山, 我相信 Russell 並沒有站在一個項目整體的立場,
並且沒有考慮許多工程化的概念, 比如 Hydration. Russell 低估了許多應用交互的複雜性.

我更傾向於讓 Web 承載更多應用的場景, 而不是讓 Web 承載更多網頁的場景.
許多軟件功能都是不必要使用 "系統級別應用" 的, 藉由 PWA 等概念,
Web 可以承載更多這樣的功能.

## Why React

不可否認社會上存在許多 "隨大流" 的想法. 但 Russell 這篇文章的受眾不會是隨大流想法.
如果真的沒有思考, 是不會去看 Russell 的文章的.

那我們為什麼使用 React? 簡單來說有三點:

1. React 可以實現我們的需求. React 提供了一套簡單的原則, 狀態數據 + JSX.
2. React 簡單易懂. 在工程上有足夠的優勢.
3. 生態好. 因為 React 有先發優勢, 可能也因為 React 在其他方面有優勢.

並不是因為:

1. "Facebook 用了 React, 所以我們用肯定沒問題." React 是 Facebook 的產物,
   但是 React 之所以成為一個開源項目, 是因為 React 解決的是一個通用且樸素的問題.
2. "React 是行業標準." 我們也不認為 React 是標準, 但不可否認 React
   對其他許多流行庫造成了深遠的影響.
3. "React 更容易被招聘." 一方面, React 並不複雜, 另一方面, React
   在我們的環境下並沒有明顯的招聘優勢.

在 Russell 介紹其他框架的時候, 我一開始難以理解 "React, Angular, etc." 中的
"etc." 不包含 Vue 等.

後來我明白了, Russell 的角度從來都不是 Web 開發者, 而是瀏覽器. Russell
是為了瀏覽器在發聲, 而不是代表 Web 開發者.

Russell 對現代化框架的定義主要圍繞在: 技術實現上不要針對老舊的 IE,
不要使用虛擬 DOM, 性能要夠好.

Russell 沒有從 React 的 API 角度說明 React 的 API
設計如何對其他所謂現代化造成的影響, 比如 state 概念, hooks 概念
(當然, hooks 屬於一種打補丁的概念, 但是它確實讓 React 的 API 變得更好用).

作為 Web 開發者, 其實就是希望 React API 可以有一層進行隔離,
讓開發者可以盡情做交互, 而不是像使用 C 一樣精細化操作 DOM.
這一點上, 其實 Svelte 做的更好, 但是 Svelte 作為框架, 侵入性更強.

而 React 作為一個庫, 而不是框架, 可以與現有任何 HTML 基礎技術棧兼容,
並且漸進式替換.

並且, React 與 "core-js, lodash, underscore, polyfills for browsers that no
longer exist, userland ECC libraries, moment.js, and a hundred other horrors"
並沒有密切的關係, 使用所謂現在框架也會遇到這樣的問題. 說白了,
這是開放式的瀏覽器生態與開發者想要避免 JS 語言歷史的坑造成的矛盾,
你不能指望所有用戶都用你開發的最新版渲染引擎.

React 並不可怕, 對於開發者, 其他渲染庫也的確值得看:

1. Svelte, 強制需要構建.
2. Lit, 以前是 Polymer, Google 的維護不足讓開發者跟進困難. (我們曾使用 Polymer)
3. Vue 經過多次大版本變化, 語法經常有破壞性變化, 與 Svelte 類似但獨有的語法更多.
   (我們曾使用 Vue 1.x, 2.x)
4. Solid, 和 React 的語法及特點最像. (我們在部分項目中在嘗試 Solid)
5. ...

但是如果要用到生產環境, 我還是建議 React.
