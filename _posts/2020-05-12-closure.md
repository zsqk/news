## 閉包
函數和對其周圍狀態（lexical environment，詞法環境）的引用捆綁在一起構成閉包（closure）。也就是說，閉包可以讓你從內部函數訪問外部函數作用域。在 JavaScript 中，每當函數被創建，就會在函數生成時生成閉包。 

參考：[MDN](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Closures)

### 閉包的特性
- 函數嵌套函數
- 函數內部可以引用函數外部的參數和變量
- 參數和變量不會被垃圾回收機制回收

### 閉包的作用
- 可以在函數的外部訪問到函數內部的局部變量。 
- 讓這些變量始終保存在內存中，不會隨著函數的結束而自動銷燬。

### 例子
比如我們定義一個計數器，正常的寫法
```
var count = 0;
function add() {
  return count += 1;
}
add(); // 1
add(); // 2
```
這樣沒問題，可以正常實現功能，也很簡單方便。但是如果我們要同時實現多個計數器呢，總不能
```
var count = 0;
function add() {
  return count += 1;
}
var count1 = 0;
function add1() {
  return count += 1;
}
var count2 = 0;
function add2() {
  return count += 1;
}
...
```
這樣一直寫吧， 所以這時候就可以使用閉包來實現
```
function add() {
  var count = 0;
  return function() {
    return count += 1;
  }
}
var fn1 = add(); // 計數器1
var fn2 = add(); // 計數器2
fn1(); // 1
fn1(); // 2
fn1(); // 3
fn2(); // 1
fn2(); // 2
fn2(); // 3
```

### 最後總結一下閉包的好處與壞處

#### 好處

- 保護函數內的變量安全 ，實現封裝，防止變量流入其他環境發生命名衝突
- 在內存中維持一個變量，可以做緩存（但使用多了同時也是一項缺點，消耗內存）
- 匿名自執行函數可以減少內存消耗

#### 壞處

- 其中一點上面已經有體現了，就是被引用的私有變量不能被銷燬，增大了內存消耗，造成內存洩漏，解決方法是可以在使用完變量後手動為它賦值為null；
- 其次由於閉包涉及跨域訪問，所以會導致性能損失，我們可以通過把跨作用域變量存儲在局部變量中，然後直接訪問局部變量，來減輕對執行速度的影響
