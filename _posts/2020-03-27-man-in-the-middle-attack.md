根據 V2EX 社區帖子, GitHub 在國內遭受大規模中間人攻擊.

什麼是中間人攻擊? 如何防範?

## 什麼是中間人

在用戶與服務器之間的任何層, 都可以稱為中間人. 包括但不僅限於:

- 本機設備的惡意軟件
- 本地路由器
- 各級電信運營商
- 國際出口

## 攻擊目的

1. 阻斷溝通.
2. 偽造身份.

大多數中間人攻擊都是為了偽造身份, 比如攻擊者不是銀行, 偽裝成銀行與客戶進行溝通
以套取密碼.

## 如何進行

1. 直接劫持並替換數據包.
2. 通過 DNS spoofing.
3. 阻斷數據包.

什麼是 DNS spoofing?

<https://en.wikipedia.org/wiki/DNS_spoofing>
<https://www.cloudflare.com/learning/dns/dns-cache-poisoning/>

我們經常遇到這種 DNS 攻擊, 如何識別與防範以後單獨寫一下.

## 如何防範

1. 本地客戶端對等加密.
2. 傳輸層加密.

本地客戶端對等加密 比較簡單, 應用範圍有限, 目的是為了防止中間人直接獲取有效信息,
提高難度.

什麼是本地客戶端對等加密? 比如本地向服務器傳輸 `123` 這個字符串, 但不直接傳輸,
而是與服務器端溝通好, 以 `!` 代表 `1`, `@` 代表 `2`, `#` 代表 `3`,
實際傳輸 `!@#`. 這樣, 如果中間人不知道二者的加解密方法, 則無法獲取有效信息.

但這種方法有很大侷限性, 比如如何保證中間人不知情? 加解密方法不能通過中間人網絡.
前期溝通成本高.

為瞭解決上述問題, 更常用的是傳輸層加密, 比如 HTTP over TLS, 也就是我們說的 HTTPS.

有人會問, TLS 與 SSL 是什麼關係? 調侃地說: 就像 ECMAScript 與 JavaScript 的關係.
中文維基百科上有一句話: "IETF將SSL進行標準化，1999年公佈第一版TLS標準文件".

TLS 是如何防範偽造身份為目的的中間人攻擊呢?

1. 客戶端發給服務器端本地可用的加密方法.
2. 服務器端看一下自己能使用哪一種, 然後告訴客戶端用什麼方法加密和公鑰證書.
3. 客戶端此時判斷服務器的公鑰證書是否可信. 證書是由第三方發放的, 如果客戶端認為
   該第三方可信, 即證書頒發者在自己的可信根內, 則認為服務器可信.
4. 客戶端與服務器端建立有效連接.

如果想進一步知道, 客戶端與服務器端如何建立有效連接, 服務器如何信任客戶端, 請看:

1. 客戶端根據公鑰加密一個隨機數據, 發給服務器端.
2. 服務器端解密後得到這個隨機數據.
3. 此時雙方都獲得了這個隨機數據, 然後雙方利用這個隨機數據再次對等加密收發數據.
