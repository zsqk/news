## 什麼是 Jamstack

只是一個概念, 可以描述一類架構.

JAM = JavaScript + APIs + Markup

在網頁應用中, HTML 是通用的 Markup language.

首先前後端分離, 不是 PHP 擅長的那種服務器端渲染.

然後需要將前端代碼自動構建為 HTML 及相關部署在 CDN 上.

### 標準寫法

按說, 完整的寫法應該是 `J.A.M. Stack`, 簡單的寫法是 `JAMStack` 或 `JAMstack`.
但是 jamstack.org 和 Netlify 給出的寫法是 `Jamstack`.

## 我們的經驗

我們曾用過 Next.js 的 Static Exporting 功能做過類似的網站. 但還是有一些的限制的,
後來就再沒用過.

現在我們更傾向於 code splitting + lazy loading 這種方案. 與 JAM 最大的不同就是
沒有 M. 不是在構建的時候生成了多個 HTML, 還是用 JavaScript 生成 DOM, 也就是
Markup.

我們選擇不使用靜態 HTML 的問題主要是路由, 普通內容站可以說在構建的時候就規劃好了
所有頁面, 但功能性站點可不是.

比如一個用戶的信息頁面我們希望是 `https://site/people/jim`, 但我們在構建的時候
並不真的清楚有多少個用戶, 用戶都在 API 中獲取. 如果要用 HTML 頁面和普通 CDN,
我們只能選擇 `https://site/people?user=jim` 這樣的方式.

### 結論

Jamstack 僅適用於內容型站點. 類似的概念不是什麼新東西了, 大多數 CMS 都是這樣的.

## Jamstack 淵源

Jamstack 是由 Netlify 提出的概念.

在 Netlify 的網站上, 有專門介紹 Jamstack 的頁面:
<https://www.netlify.com/jamstack/>.

對於內容展示型網站來說, 如果能遵循原子部署, 那麼即便數據量巨大, 理論上也是可以
使用 Jamstack 的.
